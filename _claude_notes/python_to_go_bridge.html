Comparison of Python and Go concepts for someone transitioning from Python to Go

Same idea Different in Go New concept in Go
Concept Python you know Go equivalent
Basics
Variables Same name = "Raju" name := "Raju" — Go infers type
Functions Same def greet(name): func greet(name string) {}
If / else Same if x > 0: if x > 0 {} — no colon, needs braces
For loop Different for i in range(10): for i := 0; i < 10; i++ {}
Lists / arrays Different nums = [1, 2, 3] nums := []int{1, 2, 3} — typed slices
Dictionaries Different d = {"key": "val"} m := map[string]string{}
Structure and types
Class Different class Server: type Server struct {} — structs, not classes
Methods Same idea def start(self): func (s Server) Start() {}
Inheritance Different class B(A): No inheritance — Go uses composition instead
Abstract class Different from abc import ABC type Runner interface {} — interfaces
Type hints Same idea def add(x: int) -> int: func add(x int) int {} — mandatory in Go
Error handling
Errors Very different try: ... except: val, err := doThing() — no exceptions
Error check New habit Python raises exceptions automatically You must check if err != nil {} every time
Concurrency — Go's superpower
Goroutines New in Go Threading in Python is painful go doThing() — runs in background instantly
Channels New in Go Python queues are complex ch := make(chan int) — goroutines talk safely
Packaging
Imports Same import os, sys import "fmt" — unused imports = error
pip / packages Same idea pip install requests go get github.com/...
